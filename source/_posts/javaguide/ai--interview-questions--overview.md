AI 应用开发面试覆盖 LLM 基础、Agent、RAG、系统设计四条线，题目多、交叉深。这篇学习地图帮你理清各模块的边界与复习顺序，把刷题变成可检验的闭环。

<!-- more -->

## 四大模块

- **大模型基础**：Token 与上下文窗口、采样参数、API 工程（流式、重试、限流）、结构化输出、Function Calling、应用评测。这是所有岗位的地基。
- **Agent**：Agent Loop、Memory 与 State 的边界、Prompt 与 Context 工程、MCP、Agent Skills、Harness、Workflow 与 Loop 的选型。
- **RAG**：文档解析与 Chunk 切分、Embedding 与向量数据库、混合检索、Query 改写、Rerank、GraphRAG、知识库更新与评测。
- **系统设计**：生产级架构、模型网关、调用治理、可观测性、评测体系、安全合规、实时语音 Agent。

模块之间是链路关系而非孤岛：一次真实请求会依次穿过网关、编排、模型、检索与工具，面试题也常跨模块追问，比如「设计一个知识库问答」会顺带考到召回质量、权限过滤和降级策略。

## 复习节奏

建议按周推进：第一周 LLM 基础与 API 工程，第二周 Agent 与 MCP，第三周 RAG 全链路，第四周系统设计与安全。每周末做一次 45 分钟模拟面试：15 分钟概念问答、15 分钟白板画链路、15 分钟项目深挖。把专题文章当字典查证，把面试题当 checklist 查漏——卡壳的题目标记后回到对应专题重读，再口述一遍直到能讲清「机制 + 适用场景 + 限制」。

## 输出导向的练习方法

每个模块准备一段 3 分钟口述和一道画图题（RAG 全链路、Agent Trace、网关拓扑各一张）。项目经历按「背景—挑战—方案—指标」整理，指标带统计口径与基线；比背定义更有说服力的是讲出一次真实的 Badcase：现象、根因落在哪一层、修复后的指标变化。高频交叉题（RAG 与 Memory 的区别、MCP 与 Function Calling 的分层、什么时候不该用 Agent、为什么不用微调或长上下文）要提前写成逐字稿。

## 常见误区

只刷题不做项目复盘，追问到数据口径就露馅；只准备模型和算法，忽视网关、安全、可观测这些决定能否上线的工程面；忽略 MCP、Skills、Harness 等近年新考点。

## 小结

复习的终点不是「看过」，而是能画、能讲、能举出带指标的项目证据。专题文章、面试题清单、模拟面试三轮组合，最接近真实考场状态。
