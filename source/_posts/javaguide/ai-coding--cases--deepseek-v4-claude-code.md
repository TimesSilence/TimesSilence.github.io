DeepSeek V4 Preview 发布后即开源，并提供 Anthropic 兼容接口，Claude Code 无需协议转换即可对接。本文不看跑分，直接把它放进真实代码库：用五个任务检验 V4-Pro 和 V4-Flash 分别适合干什么、在哪里会掉链子。

<!-- more -->

## 背景：为什么拿到 Claude Code 里测

对话和写作类能力，开源模型已经相当成熟；但 Agent Coding 是另一回事——自主分析项目结构、理解多文件依赖、给出能落地的工程方案，对代码能力和工具调用稳定性都有要求。技术报告和社区测试之外，更值得关注的是它进入真实仓库后的表现。V4 同时提供两款模型：V4-Pro 与 V4-Flash，均为 1M 上下文、MIT 协议；官方报告中的 Codeforces、SWE-bench 分数属于厂商公布的历史快照，不能替代自己代码库上的评测。

## 上手：两种接入方式

**配置文件法（推荐）**：编辑 `~/.claude/settings.json`，在 `env` 字段写入后端地址、模型名与 API Key——`ANTHROPIC_BASE_URL` 指向 DeepSeek 的 Anthropic 兼容端点，`ANTHROPIC_MODEL` 设为 `deepseek-v4-pro[1m]`（`[1m]` 用于请求 1M 上下文版本），并把 Haiku/子代理角色映射到 `deepseek-v4-flash`。模型 ID 与映射方式以官方接入文档为准。

**CC Switch 可视化**：需要长期在多家 Provider 之间切换时，用 CC Switch 添加自定义供应商、填 Base URL 与 Key 即可。无论哪种方式，配置完都用 `/status` 确认 model 显示为目标模型，路由才算生效。注意：兼容接口不等于完整复刻官方模型能力，工具调用与新功能要按实际任务验证。

## 实战：五个任务的分工观察

**任务一：更新多 Provider 预设模型列表。** 给一个多智能体项目更新各家 LLM 的最新模型配置并加前端下拉框。关键细节是配合 `/tavily-search` 这类搜索 Skill——纯靠模型训练数据截止日期去猜最新版本，大概率出错。带搜索的 V4-Pro 一轮完成，改动落在配置文件、环境变量示例与前端常量三处。

**任务二：数据库迁移诊断与 Flyway 集成。** 项目里两个 SQL 文件只有一个在启动时执行。V4-Pro 找到直接原因：`V2__knowledge_skill.sql` 未挂载进 Docker 容器，且项目没有迁移工具；方案是引入 Flyway，用文件命名约定管理迁移顺序。这里有个值得单列的坑：Spring Boot 4.x 大规模拆分自动配置模块后，只引入 `flyway-core` 不会触发任何迁移，启动日志也毫无输出——必须使用官方 `spring-boot-starter-flyway`。V4-Pro 第一次也踩中，贴错误日志两轮调试后修复。这个结论只适用于该案例场景，其他第三方库要分别查对应版本文档。

**任务三：面试平台对接（Flash 的边界）。** 把平台默认模型切到 `deepseek-v4-flash`，上传简历生成模拟面试：主要问题都能生成，但非思考模式下仍有两道漏答。结论：Flash 适合成本敏感、允许人工检查的批量生成，不适合不经检查就当主力。

**任务四：代码审计与多模型协同。** 让 V4-Pro 启动多个 Agent 从安全性、正确性、代码质量等维度扫描全项目，找出的 TOP 问题包括 API Key 明文存储、管理接口无权限控制、Redis `activateDefaultTyping` 反序列化漏洞、硬编码第三方密钥等。随后把问题清单交给另一个更强的模型复核并修复。思路是"低成本模型初筛、更强模型复核、测试与人工验收兜底"——审计和修复是两种能力，交叉验证更稳，但第二个模型的确认不能当成证据闭环，最终仍以测试、Review 和密钥轮换为准。具体省多少成本取决于输入长度、缓存命中与当时价格，不宜拍脑袋给倍数。

**任务五：全项目扫描分析。** 验证 V4-Pro 对项目结构、模块与待办问题的分析质量，顺带观察 Token 消耗，为成本估算积累数据。

## 分析与思考

按任务划分的使用建议：

| 场景 | 先试 | 验证重点 |
| --- | --- | --- |
| 日常对话、内容生成、简单问答 | V4-Flash | 质量、延迟、缓存命中率 |
| Agent Coding、重构、全项目分析 | V4-Pro | 工具调用、跨文件修改、测试通过率、实际成本 |
| 高风险复杂编码与独立复核 | 对比当前可用的各旗舰模型 | 任务成功率、安全边界、总成本 |

两条纪律：一是定价分高峰/空闲档且会变化，实际账单取决于缓存命中率、上下文长度与输出规模，使用前再查官方定价页；二是模型名迁移不是零成本，切换后要回归上下文长度、工具调用和错误处理路径，并留意官方公布的旧模型停用节点。

## 小结

- V4-Pro 在本文任务中能完成配置更新、迁移诊断与审计初筛；V4-Flash 更便宜，但出现了漏答，不能免检上岗。
- 多模型协同的价值在于分工：初筛、复核、验收各就各位，而不是把所有任务丢给最贵的模型。
- 官方基准只能当参考，团队自己的基准任务集（可自动验收、失败样本入库回归）才是选型的依据。
