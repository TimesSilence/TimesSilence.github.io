AI 应用开发岗位的面试，考察重心已经从「背概念」转向「讲清链路、定位问题、权衡取舍」。这篇指南先说明它与传统后端面试的差异，再给出 LLM 基础、RAG、Agent、工程化四大块的知识地图，最后落到项目讲述框架、常见考察形式与分层准备策略上。

## 与传统后端面试的差异

传统后端面试有相对成熟的评价体系：八股文考基础知识深度，项目考 CRUD、缓存、消息队列、分库分表这套成熟方法论，评价标准清晰。AI 应用开发的面试有三个明显不同：

1. **没有标准答案，只有权衡**。同一个需求可以用 Prompt、Workflow、RAG、Function Calling 或 Multi-Agent 实现，面试官关心的不是你选了哪个，而是「在你的约束下为什么这样选、代价是什么」。
2. **系统天然不可靠**。模型输出有随机性、检索可能漏召、工具调用可能超时，面试官会故意往「出错怎么办」上追问，考察你能否用工程手段兜住不确定性。
3. **真实性容易被追问击穿**。真做过的人说得出数据规模、统计口径和踩过的坑；只跑过 Demo 的人在第三层追问（基线是什么、样本量多少、上线后维护方式）就会露馅。

换句话说，后端面试奖励「答得对」，AI 面试奖励「想得清、做过、能证明」。

## 知识体系地图

四大模块不是并列的清单，而是一条请求链路的不同层次。

### LLM 基础：一次调用如何运行

Token 与上下文窗口决定容量和成本结构；采样参数（temperature、top_p）决定输出波动；流式输出、超时重试、限流、结构化输出（JSON Schema）与 Function Calling 决定后端能否稳定接住模型结果。这是所有后续模块的地基，也是初级岗位的主要考点。

### RAG：让答案落在证据上

覆盖离线索引（解析、清洗、Chunk 切分、Embedding、入库）与在线链路（Query 改写、向量与关键词混合召回、Rerank、上下文组装、引用生成），以及召回率、忠实度等评估方法。核心问题是「模型不知道的知识怎么补」，以及幻觉从哪个环节产生、如何分层治理。

### Agent：让模型驱动动作

覆盖 Agent Loop（决策-动作-观察的循环）、Memory 与 State 的边界、工具治理（Schema 校验、权限、幂等、风险分级）、MCP 等协议，以及 Workflow 与 Agent 的选型。核心问题是「模型在运行时自主决定下一步」带来了什么能力，又引入了什么失控风险。

### 工程化与系统设计：从 Demo 到生产

模型网关（路由、配额、降级、成本归因）、可观测性（Trace、Metrics、审计）、评测体系（评测集、LLM-as-Judge、发布门禁）、安全（Prompt Injection、越权、数据脱敏）、灰度与回滚。这是中高级岗位拉开差距的地方，也是「你做的能不能上生产」这个问题的答案所在。

四个模块可以互相印证：一道「设计企业知识库问答」的系统设计题，会自然追问到 RAG 召回质量、权限过滤、评测闭环和降级策略——这正是串讲练习的价值。

## 项目经验的讲述框架

项目介绍推荐按「背景—挑战—方案—指标」四段组织：

1. **背景**：谁在什么场景遇到什么问题，原来的方案（人工、规则系统、普通问答）卡在哪里，成功的判定标准是什么。
2. **挑战**：关键约束是什么——延迟预算、成本上限、权限合规、数据质量、模型能力边界。约束讲得越具体，后面的方案越有说服力。
3. **方案**：候选方案有哪些，为什么选当前这个，牺牲了什么、如何控制代价。技术栈名词应该出现在决策里，而不是单独罗列。
4. **指标**：任务完成率、P95 延迟、单任务成本、人工接管率等，必须带统计口径、样本量和基线版本。

四段缺一段都会塌：缺约束显得没有判断力，缺代价显得没上过线，缺指标则效果只是主观感受。讲的时候准备 30 秒、3 分钟两个版本，短版本只讲价值与最难的问题，长版本展开链路、一次关键优化和一个 Badcase，并主动留下你准备好的追问钩子。

## 常见考察形式

- **理论问答**：概念辨析与机制理解，如「RAG 和微调怎么选」「Memory 和 State 的边界」。答到「机制 + 适用场景 + 限制」三层才算完整，只背定义会被追问打穿。
- **系统设计**：给一个场景（智能客服、知识库问答、语音 Agent）现场设计。建议先确认需求与规模，再画数据流：接入、编排、模型、检索、工具、状态、治理，每层说清职责和不能交给模型做的事。
- **动手题**：现场写 Prompt、实现一段检索或工具调用的伪代码、在白板上画链路图。平时练习就要脱离 IDE，限时在白板或纸上把数据流画出来。

## 分层准备策略

| 经验阶段 | 复习重点 | 回答要达到的程度 |
| --- | --- | --- |
| 应届 / 0–1 年 | LLM 基础、RAG 链路、Agent Loop、简单架构 | 讲清概念，能完整描述一次模型调用或知识库问答的全流程 |
| 2–3 年 | API 工程、RAG 排查、工具治理、状态与可观测 | 能根据失败现象定位到具体环节，说明方案取舍与异常处理 |
| 3 年以上 | 模型网关、成本、安全、评测、灰度与架构演进 | 能设计完整系统，讲清容量、权限、故障恢复与质量验证 |

岗位方向也要调整权重：应用开发岗偏工程链路与项目深挖，算法岗会额外考模型原理与训练细节。无论哪个层级，2024 年后出现的 MCP、Agent Skills、Harness Engineering 等新考点都不能空窗。

## 常见误区

- 只背答案不练画图，遇到系统设计题脑子里的链路落不到纸上；
- 平均用力，Junior 硬背多租户架构、Senior 还在答 Token 定义，都是错配；
- 项目只讲功能列表，讲不出约束、权衡和度量；
- 忽视成本、安全、可观测等「不性感」但决定能否上线的工程面。

## 小结

1. AI 面试考察权衡能力、不确定性治理与项目真实性，而非概念背诵。
2. 知识地图分 LLM 基础、RAG、Agent、工程化四层，对应一条请求链路的不同环节，要能串讲。
3. 项目按「背景—挑战—方案—指标」组织，指标必须带口径与基线。
4. 考察形式分理论问答、系统设计、动手题三类，白板画链路是必备技能。
5. 按经验层级选择复习深度，并用计时模拟面试检验准备效果。
