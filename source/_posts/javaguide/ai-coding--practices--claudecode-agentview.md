同时跑多个 Claude Code 会话时，最难的不是开多少任务，而是记住哪个在跑、哪个在等确认。Agent View 和 Sub-Agent 分别解决"多会话管理"与"上下文隔离"。

<!-- more -->

## Agent View：后台会话的任务面板

终端执行 `claude agents` 打开（需 v2.1.139+，目前为 Research Preview）。每个后台会话占一行，状态图标直接告诉你哪里需要介入：黄色 `Needs Input` 在等确认，优先处理；动画表示仍在工作；绿色完成、红色失败。注意 `Completed` 分组也会收纳失败和停止的会话，别只看分组名。

已有会话输入 `/bg` 转入后台；新任务可直接从 Shell 创建：

```bash
claude --bg "修复 auth 模块里所有失败的单元测试，直到全部通过"
```

选中会话按空格弹出 Peek Panel，简单确认不必进入完整对话。提醒：后台会话由本机进程托管，关机即停，需离线运行的任务交给云端。

## 子代理的核心价值：隔离上下文

排查复杂问题时主会话往往要读几十个文件、翻一堆日志，真正有用的结论只有几条，上下文却被中间过程塞满，后面再写代码就开始"飘"。Sub-Agent 拥有独立上下文，支线调查在它自己的空间里完成，只把结论汇报回来，主会话保持干净。

内置子代理各有分工：Explore 偏快速只读搜索；Plan 用于 Plan Mode 下的只读研究；general-purpose 继承主会话工具，能执行多步骤操作。前两者不加载 `CLAUDE.md`，换取更快启动，适合纯粹的信息收集。

## 什么时候拆，什么时候不拆

适合拆的两类：一是探索性任务——跨模块调用链梳理、大仓库定向搜索，读得多、结论少，放主会话纯属浪费上下文；二是独立审查——安全、性能、并发各占一个子代理并行扫，最后汇总 findings。不适合拆的也明确：任务太小、边界模糊、代码正剧烈变化——子代理拿到的上下文很快过期，反而制造误导。

## 主代理与子代理的分工

一条好记的界线：主会话持有目标、决策权和最终验收，子代理只处理局部、明确、能独立汇报结果的任务；主会话只消费结论，不消费中间过程。需要强约束时别只靠提示词，自定义子代理放 `.claude/agents/`，用 front matter 收窄工具面：

```markdown
---
name: security-reviewer
tools: Read, Grep, Glob
---
审查目标 diff 的注入、越权、硬编码密钥问题；只报告，不改代码。
```

审查类子代理通常不需要 `Edit`/`Write`，工具越窄，行为越可预期。

## 小结

- Agent View 管"哪些会话需要我"：先看黄色，再看红色，绿色集中验收。
- 子代理管"别污染主会话"：读得多的支线任务拆出去，主代理管目标与验收，工具权限尽量收窄。
