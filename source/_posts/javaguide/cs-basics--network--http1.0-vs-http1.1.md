HTTP/1.0 与 1.1 只差一个小版本号，工程体验却天差地别：前者每个请求都要重建 TCP 连接，后者默认复用连接，还补上了 Host 头、精细化缓存、范围请求等一整套现代 Web 的地基。理解这组差异，也就理解了 HTTP/2 后来要解决什么。

<!-- more -->

## 核心差异一：短连接 vs 长连接

HTTP/1.0 默认短连接：一次请求对应一次 TCP 连接，响应到手就断开。一个含十几张图的页面就要十几次握手挥手，开销全耗在建连上。1.0 也提供了 `Connection: Keep-Alive` 请求头作为显式选项，但需要双方协商。

HTTP/1.1 把长连接（Keep-Alive）变成默认行为：TCP 连接建立后保持打开，后续请求直接复用，服务器靠空闲超时回收。想恢复短连接行为，显式发 `Connection: close` 即可。注意两点：HTTP 层的长连接本质是复用 TCP 连接，和 TCP 自身的 Keepalive 保活探测是两码事；长连接也不是永久连接，超时不用照样关闭。

## 核心差异二：管线化为什么失败

连接复用之后，1.1 还尝试过管线化（Pipelining）：不等前一个响应回来，连发多个请求，进一步摊薄延迟。但协议规定响应必须按请求顺序返回——第一个请求处理慢，后面所有响应全被堵住，这就是队头阻塞（Head-of-Line Blocking）。加上代理兼容性差、实现 bug 多，主流浏览器最终默认关闭了管线化。

这个教训直接催生了 HTTP/2：把报文切成帧、给每个请求分配流 ID，多路复用同一条连接，响应乱序到达也能拼回正确的请求——队头阻塞被从 HTTP 层消除（TCP 层的队头阻塞则留给了 HTTP/3 + QUIC）。

## 核心差异三：Host 头与虚拟主机

DNS 允许多个域名解析到同一 IP，但 1.0 的请求行只有路径：

```text
GET /home.html HTTP/1.0
```

服务器收到后无法判断客户端想要哪个站点，一台机器只能服务一个站点。1.1 强制要求 `Host` 头：

```http
GET /home.html HTTP/1.1
Host: example1.org
```

服务器据此把请求路由到对应站点，虚拟主机（一个 IP 承载多个网站）才得以成立。今天共享主机、CDN、反向代理全都建立在 `Host` 之上——HTTP/1.1 里缺少 `Host` 的请求应直接返回 400。

## 核心差异四：缓存控制的演进

1.0 的缓存靠两组原始头部：`Expires` 直接给过期时间点（受客户端时钟偏差影响），`Last-Modified` + `If-Modified-Since` 做协商——未变则回 304，变了则回 200 新内容。问题在于秒级精度太粗，且"时间没变但内容其实变了"的场景兜不住。

1.1 引入 `Cache-Control` 一统策略（`max-age` 用相对秒数避开时钟问题，`no-cache`/`no-store`/`private` 细分行为），并带来 `ETag` 实体标签：`ETag` 是内容的指纹，配合 `If-None-Match` 校验，比修改时间精确得多。`ETag` 与 `Last-Modified` 同时在时，以 `ETag` 为准。

## 其他重要增强

- **范围请求**：`Range: bytes=0-1023` 只取资源片段，响应 `206 Partial Content` 带 `Content-Range` 标明位置，断点续传和并行下载靠它实现；1.0 只能整份重传。
- **100 Continue**：客户端先发 `Expect: 100-continue` 只传请求头，服务器回 100 同意后再传大 body，避免白传被直接拒绝的请求体。
- **分块传输**：`Transfer-Encoding: chunked` 让服务器在不知道总长度时也能边生成边发送，1.0 只能靠关连接表示结束，与长连接天然冲突。
- **更多状态码**：1.0 只定义了 16 种，1.1 大幅扩充，仅错误码就新增二十余种（409、410 等）。

## 实践要点

- 抓包时看到 `Connection: close` 频繁出现，说明长连接没协商成功，检查中间代理或客户端配置。
- 静态资源缓存策略用 `Cache-Control: max-age=...` + `ETag` 组合，不要再依赖 `Expires`。
- 调试虚拟主机问题时，先确认请求里的 `Host` 头是否被代理改写。
- 理解 1.1 的队头阻塞，就明白为什么前端曾经流行"雪碧图、域名分片"，以及 HTTP/2 之后这些 hack 为什么可以退役。

## 面试追问

**HTTP/1.1 的管线化为什么没普及？** 响应必须按序返回，队头阻塞无法避免；加上代理兼容性差，浏览器默认关闭。HTTP/2 用帧+流的多路复用才真正解决 HTTP 层队头阻塞。

**长连接是 HTTP 层的还是 TCP 层的？** HTTP 的 Keep-Alive 是应用层复用 TCP 连接的约定，TCP 的 Keepalive 是传输层的保活探测报文，两者名称相似但机制无关。

**为什么 HTTP/1.1 必须有 Host 头？** 多个域名共享同一 IP 时，服务器只能靠 `Host` 区分目标站点，这是虚拟主机和 CDN 的基础；缺失 Host 的请求应返回 400。

## 小结

- 连接：1.0 短连接、1.1 默认长连接；管线化因队头阻塞失败，HTTP/2 多路复用才根治。
- 寻址：1.1 强制 `Host` 头，虚拟主机从此成立。
- 缓存：`Expires`/`Last-Modified` 演进到 `Cache-Control`/`ETag`，精度与灵活性都上了一个台阶。
- 传输：范围请求、分块传输、100 Continue 补齐了带宽利用与流式发送的能力。
