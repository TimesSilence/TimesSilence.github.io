JetBrains 重度用户常有个纠结：主流 AI 编程工具大多基于 VS Code，切过去舍不得 IDEA 的调试与重构体验，CLI 工具又缺少直观的 diff 交互。Qoder 的 JetBrains 插件提供了"一体派"选项。本文用两个 Java 后端典型任务检验它：千万级订单表的深分页优化，以及一段 150 多行祖传退款代码的重构与迭代。

<!-- more -->

## 背景与上手

后端开发者用 AI 工具大致分四类：纯 CLI 派、VS Code 派、"CLI 写 + IDEA 验收"的混合派、以及 JetBrains + 插件的一体派。Qoder 插件面向最后一类：心流不打断，一个窗口完成分析与改动。

安装很常规：**Settings → Plugins** 搜索 "qoder" 安装，登录后可在插件设置里切中文界面。一个值得提前做的可选配置是数据库连接：Qoder 支持 `@database` 上下文，能直接引用表结构与索引信息——注意它只能补充 Schema，不能替代线上执行计划和真实数据分布。

## 任务一：千万级订单表的深分页优化

故障现场：运营报表接口 `POST /api/report/orders`，请求参数 `{"page": 1000000, "size": 10}`。代码用分页插件直接查，`page=1000000` 时 MySQL 实际执行 `LIMIT 9999990, 10`——扫前 1000 万行再丢弃，超时是必然结果。

工作方式的变化从这里开始：开发者的角色从执行者转为验收者，负责整理思路、给出明确目标、添加 `@database` 上下文。Qoder 随后完成的事包括：

- **联合诊断**：定位代码入口，结合 Schema 列出深分页、排序字段无索引等候选原因（结论仍需慢查询日志与 `EXPLAIN ANALYZE` 验证）；
- **多套方案**：含延迟关联查询——子查询只返回 ID、利用覆盖索引快速定位再回表；另附一个分页总数的估算方案（按主键索引页数与页内平均行数估总量），它只适合允许近似结果的场景，账务、结算类业务不能直接用；
- **落地与验证**：选定"延迟关联 + 索引优化"后，重构分页方法（含最大页码限制）、索引脚本在 IDE 内直接执行、补齐单测、生成带 JIT 预热的压测代码，最后输出工作总结，还能基于当前 diff 生成提交说明。

本次演示从输入上下文到产出候选改动约 10 分钟，但执行计划复核、压测、Code Review 与上线验证不在其中。尤其注意：JIT 预热只减少冷启动对基准的干扰，判断优化是否有效，还得记录硬件、JDK 与 GC、数据分布、并发模型和 p95/p99。

## 任务二：祖传退款代码的梳理、重构与迭代

`applyRefund` 方法 150 多行、无注释、魔法值遍地，新需求是加一条风控规则：72 小时内存在未完成订单的用户禁止退款。直接改没人敢动，于是分三步走。

**第一步，只读梳理。** 让 Qoder 结合数据流讲清完整业务流程并补注释，同时提交存量 Schema 减少它对表结构的猜测。它逐个分支梳理并归纳出接口逻辑与特殊规则点——注释和数据流仍需逐项对照原实现与产品规则。

**第二步，带回归基线的重构。** 指令里明确要求：参考《重构》的方法、先为现有行为补特征测试、输出未覆盖分支、不得用覆盖率代替新旧等价性验证。Qoder 的做法是新建 `RefundServiceRefactored` 而非直接改原类：校验、金额计算、单号生成分别抽成 `RefundValidator`、`RefundCalculator`、`RefundNoGenerator`，主方法只剩十几行。这为新旧对照留了空间，但"新建一个类"本身不等于安全重构——还需要明确调用路由或特性开关、用同一批输入比较新旧结果、约定旧实现下线时间，否则两份逻辑会长期漂移。单测分支覆盖率约 80% 也只说明路径被执行过，金额、状态迁移等关键路径还要靠特征测试与新旧结果对照。

**第三步，一行指令做迭代。** 结构理顺后，新增 72 小时风控规则只需一条指令，职责单一的校验框架和配套测试已经就位，增量改动容易回归。

**记忆沉淀。** 任务完成后 Qoder 会把项目特点（如"延迟关联优于游标分页"）、编码规范、业务规则写入 Memory。建议正式规则仍放在可评审、可版本化的项目文档里，Memory 只作辅助上下文，并定期清理过期条目。

## 分析与思考

两个案例体现的核心能力是"工程感知"：从 `RefundService` 自动追到 Mapper 与校验器，无需手动喂上下文；分析、改动、测试生成在一个窗口内闭环。同时边界也清晰：方案的选择与权衡（为什么选延迟关联而不是游标分页——后者影响用户体验）AI 不替你做；事务注解 `rollbackFor` 只在代理调用、异常继续抛出时生效，自调用或吞异常要另行处理；重构质量要用《重构》《阿里巴巴 Java 开发手册》这类标尺去衡量。

用好它的前提是保持对底层原理的学习：数据库索引、JVM、并发——这些"地基"知识不会因为 AI 而贬值，反而是评审 AI 输出的标尺。

## 小结

- Qoder 插件把 Agent 的分析与编码能力装进 IDEA，适合不想切换工具的 JetBrains 用户。
- 深分页任务的关键是 `@database` 上下文 + 延迟关联方案 + 压测口径意识；重构任务的关键是先立回归基线，再动结构。
- 开发者的工作重心从"写"转向"拆任务、审方案、验收结果"，评审能力因此比以前更重要。
