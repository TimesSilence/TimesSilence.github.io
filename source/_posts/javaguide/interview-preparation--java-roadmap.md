Java 后端的知识面广，但真正决定成败的不是学了多少，而是每个阶段是否达到了可检验的标准。这份路线按七个阶段推进，每阶段给出目标、核心主题、验收标准（能脱稿回答什么问题）和时间建议，让你随时可以判断"这一阶段我过关了没有"。

<!-- more -->

## 使用方式

每个阶段先看目标，再按核心主题逐个击破，最后用验收标准自测：合上书能讲清楚，才算过；讲不清的回到资料重学。时间建议以每天 3–4 小时有效学习计，基础好可压缩，零基础适当放宽。不要追求一次学完全部目录，前一阶段的验收标准没过，不要进入下一阶段。

## 阶段一：Java 语言基础（3–5 周）

**目标**：能独立写出结构清晰的小程序，理解语言机制而不只是语法。

**核心主题**：基本类型与运算、流程控制、面向对象（封装/继承/多态/接口）、常用类（String、日期、BigDecimal）、异常体系、泛型、反射与注解、IO 与序列化、Java 8+ 新特性（Lambda、Stream、Optional）。

**验收标准**：能回答 String 为什么不可变、`==` 与 equals 的区别、深拷贝与浅拷贝、受检与非受检异常的划分依据、泛型擦除带来的限制、反射的代价是什么。

## 阶段二：集合、并发与 JVM（4–6 周）

**目标**：建立对 Java 内功的框架性理解，这是面试区分度最高的部分。

**核心主题**：集合框架（ArrayList、LinkedList、HashMap、ConcurrentHashMap 的结构与扩容）、并发基础（线程生命周期、synchronized、volatile、JMM）、并发工具（ThreadPoolExecutor、AQS、CountDownLatch、ThreadLocal）、JVM（内存区域、类加载机制、GC 算法与收集器、常用调优参数）。

**验收标准**：能画出 HashMap 的存取流程并解释链表转红黑树的阈值；能讲清 volatile 保证什么、不保证什么；能说出线程池核心参数与拒绝策略的组合效果；能解释一次 Young GC 的完整过程；能读懂一段 OOM 日志并定位可能原因。

## 阶段三：开发框架（3–4 周）

**目标**：能用主流框架独立完成一个 CRUD 项目，并理解框架替你做了什么。

**核心主题**：构建工具（Maven 依赖管理与冲突解决）、Spring（IoC、AOP、Bean 生命周期、事务传播）、Spring MVC 请求流程、Spring Boot 自动装配、MyBatis 的映射机制与一级二级缓存。

**验收标准**：能手写一个最小 IoC 容器演示依赖注入；能解释 Spring 事务在什么情况下失效；能描述 Spring Boot 启动时自动配置的加载链路；能对比 `#{}` 与 `${}` 的差异及 SQL 注入风险。

## 阶段四：数据库与缓存（3–4 周）

**目标**：掌握后端持久层的核心：MySQL 与 Redis。

**核心主题**：MySQL（索引的 B+ 树原理、Explain 分析、事务隔离级别与 MVCC、锁、慢查询优化、分库分表思路）、Redis（五种数据结构及底层实现、持久化 RDB/AOF、过期与淘汰策略、缓存穿透/击穿/雪崩、主从与哨兵）。

**验收标准**：能解释为什么用 B+ 树而不是二叉树或哈希做索引；能分析一条慢 SQL 并给出优化方案；能讲清可重复读是如何通过 MVCC 实现的；能设计一个防缓存击穿的方案并说明取舍；能说明 Redis 单线程模型为什么快。

## 阶段五：分布式与中间件（4–5 周）

**目标**：理解单机到分布式的跨越中引入了哪些新问题，以及主流组件如何解决。

**核心主题**：分布式理论（CAP、BASE、一致性协议常识）、消息队列（Kafka/RocketMQ 的投递语义、积压与幂等）、注册中心与 RPC（Nacos、Dubbo 的调用链路）、分布式锁与分布式事务（2PC、TCC、本地消息表、Saga）、搜索引擎（Elasticsearch 的倒排索引与写入流程）。

**验收标准**：能回答 MQ 如何保证不丢消息、消费重复怎么办；能讲清一次 Dubbo 调用的完整链路；能对比几种分布式事务方案的适用场景；能解释 ES 为什么近实时以及段合并的影响。

## 阶段六：工程化与项目实战（持续进行）

**目标**：把知识转化为可交付的能力，项目是最有说服力的证明。

**核心主题**：Git 协作流程、Linux 常用命令与排查工具、Docker 容器化部署、CI/CD 基本概念、设计模式（单例、工厂、代理、观察者等高频模式）、系统设计方法（从估算、接口、存储到扩展性的完整推演）。

**验收标准**：有一个能跑在服务器上、README 写清架构与难点的项目；能讲出项目中至少两个技术选型的理由和踩过的坑；能在白板上演算一个常见系统设计题（如短链、秒杀、Feed 流）。

## 阶段七：AI 能力扩展（1–2 周，可选）

**目标**：顺应岗位趋势，掌握后端工程师与 AI 结合的常见切入点。

**核心主题**：大模型 API 调用与 Prompt 工程基础、Embedding 与向量检索、RAG 的基本链路（切分、向量化、召回、生成）、Function Calling 与 Agent 的初步概念。

**验收标准**：能独立写一个调用 LLM API 的小工具；能讲清 RAG 与微调各自解决什么问题；能在项目中设计一个最小可用的知识库问答功能。

## 常见误区

- **囤积资料**：收藏一百篇教程不如把一阶段验收标准全部过一遍。
- **只看不动手**：并发、JVM、MySQL 的验收题，不写代码实验一遍很难真正讲清。
- **跳阶段**：框架没懂原理就学分布式，只会留下一地概念碎片。
- **忽视表达**：每个知识点学完，试着对空气讲三分钟，讲不顺就是没学会。

路线的本质是取舍：先让主干立起来，枝叶在学有余力时再补。
