系统设计基础模块收录的是后端开发中最容易被忽视、却长期决定维护成本的一类能力：接口怎么设计、需求怎么落地、代码怎么写干净、改动怎么不出事。本文给出主题分组、推荐学习顺序和每个主题的一句话说明，作为本模块的导航。

<!-- more -->

## 为什么先打工程基础

缓存、消息队列、分库分表这类"硬核"话题决定系统能跑多快，而接口设计、命名、测试、重构这类工程基础决定系统能活多久。很多项目恰恰倒在后者：接口契约含糊导致联调反复返工，命名混乱导致没人敢动旧代码，没有测试导致重构停摆，最后每个需求都变成在泥地里盖楼。先补基础再学上层建筑，投入产出比最高。

## 主题分组

本模块的五个主题可以分成三组。

### API 契约

- **RESTful API 简明教程**：围绕资源建模讲清 URL 设计、HTTP 方法语义和状态码规范，让接口可读、一致、可演进。

### 工程过程

- **软件工程简明教程**：梳理软件危机、开发过程模型（瀑布、迭代、敏捷）与工程化基本概念，回答"软件开发为什么不只是写代码"。

### 代码质量三件套

- **代码命名指南**：变量、函数、类的命名原则与常见反例，用名字降低沟通成本。
- **单元测试**：测试的边界、Mock 与 Stub 的分工、测试金字塔与 JUnit 基础，让测试服务于变更信心而不是覆盖率数字。
- **代码重构指南**：识别重复代码、过长函数等坏味道，掌握在测试保护下小步改善结构的方法。

三组之间存在依赖：命名和重构都建立在"能读懂代码意图"之上，重构的安全感又来自测试；API 设计和软件工程则为这些代码层实践提供契约与过程背景。

## 推荐学习顺序

1. **软件工程简明教程**——先建立全局视角：需求、设计、开发、测试、交付、维护是一个完整过程，写代码只是其中一环。
2. **RESTful API 简明教程**——理解系统对外契约怎么设计，之后写代码时自然会把"接口使用者"放进考量。
3. **代码命名指南**——从最小颗粒度改善可读性，成本最低、见效最快。
4. **单元测试**——先学会写测试，因为它是下一步重构的安全网，顺序不要反过来。
5. **代码重构指南**——有了测试保护，再系统学习坏味道识别与重构手法，把前面的积累转化为持续改善的能力。

如果为面试速成，可以按"RESTful API → 单元测试 → 重构"的优先级抓高频题；如果为长期功底，建议按完整顺序走一遍，并配合真实代码动手练。

## 使用建议

- 每篇都配有具体示例，读完立刻在当前项目里找一处对应问题动手改，比纯阅读有效得多。
- 规范类内容（命名、API 设计）适合团队拉齐共识后写进代码评审清单和 CI 检查，而不是靠口头约定。
- 测试和重构是长期习惯，建议从"每次提交顺手留一处改进"的童子军规则开始，不必等专门的重构窗口。

## 小结

- 本模块分三组：API 契约（RESTful）、工程过程（软件工程）、代码质量三件套（命名、测试、重构）。
- 推荐顺序：软件工程 → RESTful API → 命名 → 单元测试 → 重构，其中测试必须先于重构。
- 工程基础不显眼，但它决定一个系统能否被团队长期维护下去。
