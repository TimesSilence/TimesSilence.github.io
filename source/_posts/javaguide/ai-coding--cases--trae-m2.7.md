Trae 是字节跳动推出的 AI 编程 IDE，基于 VS Code 生态，支持接入自定义大模型。本文以 MiniMax M2.7 为例（换其他模型流程一致），用两个场景走完整流程：一次线上接口超时的排查与止血，以及把 Redis 慢查询指令从 C 源码复刻到 Go。

<!-- more -->

## 背景与接入

图形化 IDE 的价值在于把日志、断点、diff 审查和 Agent 对话放进同一窗口，适合偏好可视化验证的团队。接入自定义模型只需四步：下载安装 Trae；到模型平台创建 API Key；在设置里点"Add Model"选择"Other Models"；填入模型 ID（如 `MiniMax-M2.7`）与 Key，无报错即接入成功。

两个场景的选择有讲究：场景一考"在多处使用 Redis 的项目里快速定位根因"，场景二考"跨语言重构与源码理解"，都是日常后端开发中耗时但典型的活。

## 场景一：接口超时的止血与根因定位

故障现场（脱敏复刻）：列表查询接口返回 500，异常堆栈的关键字是 `Read timed out`，对应代码段是一次普通的 `get(key)`。按经验这只是表象——项目里多处用到 Redis，逐一排查太慢。

**收敛问题空间。** 把堆栈和接口信息交给模型，它很快给出四种候选根因：Redis 宕机或无响应、连接池配置太小高并发下耗尽、连接泄漏、服务端负载过高。问题空间从"N 处 Redis 调用"压缩到"4 个假设"，这正是 AI 辅助排查的核心价值。进一步追问后，模型梳理出调用链：列表接口被权限切面拦截，切面内的缓存读取夯住连接池——并指出这段代码缺乏降级策略，这一点连复盘时人都没意识到。

**止血方案要过人工这一关。** 模型给的方案一（清缓存并临时关闭权限校验）相当激进，生产环境未必能接受；方案三（Redis 不可用时降级为本地缓存或直查数据库，避免级联失败）更稳妥。综合后下达 hotfix 指令：建 `hotfix/redis-exception-handler` 分支、所有 Redis 操作加 try-catch、异常时降级查库、补 JVM 本地缓存、写测试、备回滚。生成的本地缓存实现值得一提：`ConcurrentHashMap` 存数据、守护线程定时清理过期项、容量触顶时按 LRU 淘汰一半，TTL 默认 5 分钟——容错设计上是有章法的。

**根因定位。** 止血后做全局分析：常规 get 指令按 Redis 的处理能力估算远不该超时，问题大概率在代码层。模型最终给出根因——不当的数据结构设计配合 scan 操作导致连接池夯死，并建议通过优化数据结构降低读写时间复杂度。整个推理链从异常栈帧到调用链路再到根因，完整闭环。

## 场景二：慢查询指令的 C→Go 复刻

目标是在 mini-redis（goroutine-per-connection 模型、实现 RESP 协议的 Go 缓存项目）里复刻 Redis 的慢查询功能。按传统流程，读无注释源码、梳理逻辑、设计、测试，保守估计要几个工作日；这次把源码阅读和技术文档整理交给 AI。

流程分三段：

1. **源码理解**：让模型通读 Redis 慢查询实现，输出存储机制、阈值配置、收集流程、查询接口的技术文档。它对慢查询切面在主流程上的定位准确，注释加在关键路径上。
2. **方案移植**：把设计文档带进 mini-redis 做可行性分析。模型准确定位到项目里可直接复用的链表结构体，按项目编码规范生成 Go 风格结构体，并基于项目的协程模型找到时间测量的切面位置，完成前置计时与后置统计。
3. **TDD 落地**：指定测试驱动开发流程后，模型根据测试反馈自循环修复。验收时把 `slowlog-log-slower-than` 设为 0（记录所有命令），`slowlog get` 按链表头插法以时间降序输出，行为与预期一致。整个梳理加开发不到一小时。

也有两处需要人工介入：模型把 `slowlog` 指令独立成文件，而项目惯例是统一放进 `command.go`——权衡后保留其划分、手动调整布局；过程中另有两次生成的代码不符合项目风格（如错误处理方式），需要手改。

## 分析与思考

两个场景暴露出的规律一致：

- **擅长的事**：快速收敛问题范围、跨模块关联代码与 Schema、分层输出止血与长期方案、在测试反馈中自修复。
- **必须人兜的事**：方案可能激进（清缓存、关校验这类操作要人工把关）；生成代码与既有工程规范需要磨合；边界条件的防御性代码建议人工补——AI 能走到 90%，剩下 10% 靠自己；长流程迭代要留意上下文记忆衰减。
- **使用方法**：给足完整上下文（约束、规范、项目结构）；复杂任务分阶段确认；缓存策略、降级方案这类关键决策人来做；明确指定 TDD 能显著减少返工。

## 小结

- IDE 内 Agent 的工作流是"复现 → 假设树 → 验证 → 最小 patch → 回归"，排查类任务尤其受益。
- 跨语言复刻的可行路径：先让 AI 出源码导读文档，再做目标项目的可行性分析，最后 TDD 落地。
- 工具缩短的是"从想法到代码"的时间；对连接池机制、scan 复杂度、Go 工程规范的判断力，仍是开发者自己的功课。
