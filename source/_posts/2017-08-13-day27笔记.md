## 本篇目标

读完本篇你应该能够：说出类加载的三步流程与六种触发时机；描述三层类加载器与双亲委派的运作方式；用三种方式获取 Class 对象；用反射操作构造器、方法、字段；说清反射的价值与代价；盘点 JDK 5~8 的代表性特性。

## 类加载：从 .class 文件到 Class 对象

程序用到某个类时，如果它还没进内存，JVM 会完成三步：**加载**（把 .class 文件读入内存，创建对应的 `Class` 对象）、**连接**（验证字节码合法性、为静态变量分配内存并设默认值、把符号引用解析为直接引用）、**初始化**（执行静态代码块和静态变量赋值，也就是我们熟知的类初始化）。

触发加载的时机有六种：创建实例（new）、访问或赋值静态变量、调用静态方法、反射（`Class.forName`）、初始化子类（父类会先加载）、`java` 命令运行主类。记住规律：**第一次"主动使用"时加载，且整个生命周期只加载一次**——这正是上一篇饿汉式单例线程安全的根基。

## 类加载器与双亲委派

加载动作由类加载器完成，JVM 内置三层：

- **Bootstrap ClassLoader（引导类加载器）**：C++ 实现，加载 `JAVA_HOME/lib` 下的核心类库（String、System 这些）。
- **Extension ClassLoader（扩展类加载器）**：加载 `lib/ext` 目录的扩展 jar。
- **System ClassLoader（系统/应用类加载器）**：加载 classpath 上的类，也就是我们自己写的代码。

三者之间不是继承而是**组合**，并遵守双亲委派：一个类加载器收到加载请求后，先委托父加载器去尝试，父加载器不行再自己加载。这个设计的价值是**安全与稳定**——你自己写一个 `java.lang.String` 也永远轮不到被加载，因为请求最终会被 Bootstrap 用 JDK 正主处理掉，核心 API 不会被篡改。

## 反射：程序在运行时解剖自己

普通代码是"编译时确定一切"：new 哪个类、调哪个方法，写死在源码里。反射则允许**在运行时**获取任意类的信息、创建任意对象、调用任意方法。为什么需要这种能力？因为框架写的时候根本不知道用户的类叫什么——Spring 只能约定"你把类名写在配置里，我来加载"，这个"按名字加载类并创建对象"的动作，只有反射能做到。

获取 Class 对象有三种方式：

```java
// 1. 通过对象：已有实例时
Class<?> c1 = "hello".getClass();

// 2. 通过类名.class：编译期已知类型时
Class<?> c2 = String.class;

// 3. Class.forName：只有字符串类名时，框架最常用
Class<?> c3 = Class.forName("java.lang.String");
```

三者拿到的是同一个 Class 对象（类只加载一次）。`forName` 的意义在于**把类名从代码挪进配置文件**，改配置即改行为，无需重新编译——这就是"配置驱动"的起点。

经典案例是榨汁机：配置文件里写一行类名 `Apple` 或 `Orange`，程序读出来反射创建实例，想换水果只改配置文件：

```java
BufferedReader br = new BufferedReader(new FileReader("config.properties"));
Class<?> clazz = Class.forName(br.readLine());   // 从配置文件读类名
Fruit fruit = (Fruit) clazz.newInstance();       // 反射创建实例
new Juicer().run(fruit);                          // 面向接口编程，无需改代码
```

### 操作构造器、字段、方法

```java
Class<?> clazz = Class.forName("com.example.Person");

// 构造器：newInstance() 只走无参构造，带参构造要显式获取
Constructor<?> ctor = clazz.getConstructor(String.class, int.class);
Object p = ctor.newInstance("张三", 20);

// 字段：getDeclaredField 能拿私有字段，但要 setAccessible 开后门
Field nameField = clazz.getDeclaredField("name");
nameField.setAccessible(true);
nameField.set(p, "李四");
System.out.println(nameField.get(p));

// 方法：方法名 + 参数类型定位，invoke 触发执行
Method eat = clazz.getMethod("eat", int.class);
eat.invoke(p, 10);
```

要点：`getXxx` 只拿 public（含父类继承的），`getDeclaredXxx` 拿本类所有声明（含私有）但不含继承的；操作私有成员必须 `setAccessible(true)`。一个经典应用是**越过泛型检查**：泛型只在编译期存在，运行期被擦除，所以可以用反射往 `ArrayList<Integer>` 里塞字符串——这个"漏洞"本身就是泛型擦除机制最好的证明。

## 反射的代价与动态代理

反射不是免费的，代价有三：**性能**，反射调用比直接调用慢（要做安全检查、无法被 JIT 内联优化，虽然现代 JVM 已大幅改善，热点路径上仍应避免）；**破坏封装**，`setAccessible(true)` 让 private 形同虚设，类的约束被绕过；**可读性**，满屏 invoke 的代码远比直白的方法调用难维护。所以反射的定位是**框架级工具**，不是日常业务代码的常规武器。

反射最重要的应用是**动态代理**：运行期生成一个实现同样接口的代理对象，在原方法执行前后织入统一逻辑（日志、事务、权限），而不用改原类。JDK 提供 `Proxy.newProxyInstance(类加载器, 接口数组, InvocationHandler)`，所有方法调用都被路由到 `InvocationHandler.invoke` 里统一处理——Spring AOP 的底层就是它（接口代理）和 CGLIB（继承代理）。

## JDK 5~8 特性回顾

**JDK 5 是语言现代化的起点**：

- **泛型**：把类型检查提前到编译期，消除强制转换；
- **枚举 enum**：本质是"有限实例的多例类"，构造器私有，自带 `values()`、`valueOf()`，可在 switch 中使用，比 int 常量安全得多；
- **自动装箱拆箱**：int 与 Integer 自动互转，省心但要警惕空指针与缓存陷阱；
- **增强 for、可变参数、静态导入**：语法层面的减负。

**JDK 7 继续打磨细节**：字符串入 switch、菱形泛型 `new ArrayList<>()`、数字字面量下划线（`1_000_000`）、多异常合并 catch，以及最重要的 **try-with-resources**：

```java
try (BufferedReader br = new BufferedReader(new FileReader("a.txt"))) {
    System.out.println(br.readLine());
}   // 自动关闭，不再需要 finally 里嵌套判空
```

**JDK 8 是函数式的分水岭**：lambda 表达式让"行为"可以当参数传递；接口可以有 default 方法（否则给 Collection 加 stream 方法会摧毁所有实现类）；Stream API 把集合操作从"怎么遍历"变成"要什么结果"：

```java
list.stream()
    .filter(s -> s.length() > 3)
    .map(String::toUpperCase)
    .forEach(System.out::println);
```

顺带解释一个老问题：局部内部类访问方法的局部变量为什么要求 final（JDK 8 起放宽为"事实上的 final"）？因为内部类对象可能比方法活得久，方法弹栈后局部变量已销毁，内部类持有的其实是变量的副本——副本必须不可变，两份数据才不会不一致。

## 小结

- 类加载三步走（加载、连接、初始化），首次主动使用时触发，一生一次。
- 三层类加载器加双亲委派：先问父亲，既保安全又保核心类不被替换。
- 反射三件套：Class 对象三种获取、构造/字段/方法反射调用、`setAccessible` 破封装；价值在"运行期的动态性"，是框架的基石。
- 反射的代价是性能、封装与可读性，业务代码慎用，框架代码重用；动态代理是它最耀眼的应用。
- JDK 5~8 的演进主线：泛型与枚举让类型更安全，try-with-resources 让资源管理更优雅，lambda 与 Stream 让 Java 迈入函数式。
