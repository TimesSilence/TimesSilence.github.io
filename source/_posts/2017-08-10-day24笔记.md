## 本篇目标

读完本篇你应该能够：说清进程与线程、并行与并发的区别；用两种方式创建线程并解释为什么推荐 Runnable；画出线程生命周期的状态流转；用 sleep、join 控制线程协作；用 synchronized 的两种形态解决线程安全问题；解释死锁产生的四个必要条件。

## 进程与线程：资源分配与调度的两级单位

进程是操作系统分配资源的最小单位，线程是 CPU 调度的最小单位。启动一个 JVM 就是启动一个进程，进程内至少跑着主线程和垃圾回收线程——所以你写的第一个 HelloWorld 程序其实已经是多线程的。

关键区别在于**资源共享方式**：进程之间内存相互独立，切换代价高；同一进程内的线程共享堆内存和方法区，每个线程只独占自己的虚拟机栈和程序计数器。共享内存带来了通信的便利，也埋下了本篇后半段的线程安全问题。

顺带区分两个高频词：**并行**是多个任务在多核上真正同时执行，好比左手右手各操作一台电脑；**并发**是单核靠时间片轮转造成的"看似同时"，好比一个人先回甲的消息再立刻回乙的消息。Java 线程模型对两者透明——代码不感知底层是哪种，这既是抽象的好处，也是问题难排查的原因：同一个 bug 在多核机器上可能立刻暴露，在单核上却潜藏很久。

多线程的应用场景随处可见：下载工具开多条线程分段下载、聊天软件同时维持多个会话、服务器同时响应成百上千的客户端请求——凡是"一个人干不过来"或"一个人干太浪费"的活，都是并发的舞台。

## 创建线程的两种方式

### 方式一：继承 Thread

```java
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("子线程执行中");
    }
}

MyThread t = new MyThread();
t.start();   // 注意是 start()，不是 run()
```

### 方式二：实现 Runnable

```java
class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println("任务执行中");
    }
}

Thread t = new Thread(new MyRunnable());
t.start();
```

**为什么推荐 Runnable？** 三个理由：其一，Java 单继承，继承了 Thread 就无法再继承其他类，而接口可以多实现；其二，Runnable 把"任务"和"执行机制"解耦，同一个 Runnable 可以交给不同线程、甚至交给线程池反复执行，继承 Thread 则把两者焊死；其三，看 Thread 的源码就知道，`start()` 内部调用的 `run()` 会判断成员变量 `target` 不为空则执行 `target.run()`——继承是重写，实现是委托，委托天然更灵活。

新手最常犯的错是**调用 `run()` 代替 `start()`**：前者只是普通方法调用，在当前线程同步执行，根本没有开启新线程。`start()` 才会让 JVM 向操作系统申请真正的线程并回调 `run()`。

## 线程生命周期与协作控制

线程有五种状态：新建（new 之后）、就绪（start 之后等 CPU）、运行（分到时间片）、阻塞（sleep/wait/等锁）、死亡（run 结束）。重点掌握两个协作方法：

**sleep(毫秒)**：让当前线程进入计时等待，**不释放锁**，醒来后回到就绪态重新竞争 CPU。它是 `Thread` 的静态方法，永远作用于当前线程——`t.sleep(1000)` 让 t 睡，这个语义常被误读。

```java
new Thread(() -> {
    for (int i = 0; i < 10; i++) {
        System.out.println(Thread.currentThread().getName() + ": " + i);
        try {
            Thread.sleep(100);   // 模拟耗时，降低切换频率便于观察
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
    }
}).start();
```

**join()**：谁调用就等谁。主线程里写 `t1.join()`，主线程就停住直到 t1 执行完再继续；`join(30)` 则最多等 30 毫秒。它是"线程之间讲顺序"的最直接手段。

另有 `setDaemon(true)` 把线程设为守护线程——当所有非守护线程结束时，守护线程随之退出（垃圾回收线程就是守护线程）；`yield()` 礼让 CPU 只是建议，调度器可以无视。

## 线程安全与 synchronized

经典反例是四个窗口卖 100 张票：如果不加控制，`tickets--` 不是原子操作，它实际包含读、减、写三步，线程完全可能在"读完还没写回"的间隙被切走，于是两个窗口卖出同一张票，甚至卖出第 0 张、第 -1 张。线程安全问题的根源就一条：**多个线程并发读写同一份共享数据**。反过来说，各线程只用自己的局部变量，或者共享数据只读不写，就天然安全——这也是函数式风格在并发时代受宠的原因。

synchronized 提供互斥：同一时刻只有一个线程能持有某把锁，其余线程在锁外排队。

### 同步代码块

```java
private int tickets = 100;
private final Object lock = new Object();

public void run() {
    while (true) {
        synchronized (lock) {          // 锁对象必须是多个线程共享的同一个对象
            if (tickets <= 0) {
                break;
            }
            System.out.println(Thread.currentThread().getName()
                    + " 卖出第 " + tickets-- + " 号票");
        }
    }
}
```

锁对象可以是任意对象，但**必须是同一把锁**——用匿名对象或各自 new 一个等于没锁；也不能锁会变化的引用。

### 同步方法

用 synchronized 修饰方法，整个方法体都在锁内。锁对象是隐式的：非静态同步方法锁 `this`，静态同步方法锁类的 `Class` 对象。判断两段代码是否互斥，只看它们抢的是不是同一把锁。

同步的代价是串行化和切换开销，所以原则是**锁的粒度尽量小**：只锁真正操作共享数据的那几行，这也是同步块比同步方法更常用的原因。

## 死锁：自己亲手制造一次

同步嵌套时，两个线程各持一把锁又互等对方的锁，程序就僵死了，这就是死锁。经典的"筷子问题"：

```java
private static final String LEFT = "左筷";
private static final String RIGHT = "右筷";

public static void main(String[] args) {
    new Thread(() -> {
        synchronized (LEFT) {
            System.out.println("甲拿到左筷，等右筷");
            try { Thread.sleep(100); } catch (InterruptedException e) { }
            synchronized (RIGHT) {          // 甲持左等右
                System.out.println("甲开吃");
            }
        }
    }).start();

    new Thread(() -> {
        synchronized (RIGHT) {
            System.out.println("乙拿到右筷，等左筷");
            synchronized (LEFT) {           // 乙持右等左
                System.out.println("乙开吃");
            }
        }
    }).start();
}
```

死锁产生需要四个条件同时成立：互斥、持有并等待、不可剥夺、循环等待。破掉任意一条即可避免，工程上最常用的办法是**统一加锁顺序**（所有线程都按相同顺序申请锁），其次是避免嵌套加锁、用带超时的 `tryLock` 代替无限等待。排查时用 `jstack` 打印线程快照，死锁会被直接标出来。

## 小结

- 进程分资源，线程抢 CPU；线程共享堆内存，便利与风险同源。
- 创建线程推荐实现 Runnable：绕开单继承限制，任务与执行解耦；启动只能用 `start()`。
- 生命周期五态流转中，sleep 不释放锁、join 用于排序，是协作的基本工具。
- 线程安全问题源于共享数据的并发读写，synchronized 用互斥解决，锁粒度越小越好。
- 死锁四条件缺一不可，统一加锁顺序是最实用的预防手段。
