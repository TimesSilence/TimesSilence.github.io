# 每日技术文章写作手册

本站（Hexo 8 + Butterfly）每日更新一条「技术动态」文章线的执行手册。定时任务与人工写作都遵循本手册。

## 内容定位

- 每日一篇**技术博客**：以技术问题、机制原理或工程方法为主体，写得像一篇独立的深度技术文章
- **不是新闻**。近期技术动态只作选题线索与开头引子（一句话交代背景即可），不写"发生了什么/谁发布了什么"的新闻体章节；全文 90% 以上篇幅必须是技术分析
- 读者画像：有后端/AI 工程经验的开发者。读者读完应获得可迁移的知识与方法，而不只是"知道了这件事"
- 标题即技术主题（如"AI 代码评审怎么做得又准又省"），避免新闻式标题（如"阿里开源 XXX"）

## 选题与查重（必须执行）

1. 运行 `node tools/list-existing-topics.mjs` 获取全站已有文章的标题与标签清单
2. 选题不得与清单中的文章主题重复。允许"同一技术的不同切面"（如已有 RAG 基础，仍可写某个新发布的 RAG 框架），但标题与切入点必须明显区分
3. 优先选择：与站点主线（Java/后端/分布式/AI/Agent/AI 编程）相关的动态

## 信息源（中英混合）

- 英文：Hacker News 首页热点、GitHub Trending、InfoQ、官方博客/CHANGELOG、arXiv 热点
- 中文：掘金热榜、少数派、阮一峰科技爱好者周刊、官方公众号/博客
- 事实纪律：只写从信息源核实到的内容；版本号、数字、发布日期必须有出处；拿不到出处的就不写或定性描述。绝不编造

## 文件规范

- 路径：`source/_posts/daily/YYYY-MM-DD-<英文-slug>.md`
- front matter（字段完整，缺一不可）：

```yaml
---
title: "中文标题：主题讲清楚"
date: YYYY-MM-DD HH:mm:ss
permalink: daily/<英文-slug>/
categories:
  - 技术动态
tags:
  - 2-5 个标签，优先复用已有标签（见查重清单）
description: "一句话摘要，单行 YAML 字符串"
---
```

- permalink 全站唯一，写前对照查重清单确认未占用

## 正文结构（正文 1500–2800 字）

1. 摘要（1-3 句：技术问题是什么 + 本文讲清什么）+ 空行 + `<!-- more -->`
2. `## 问题/矛盾`：这个技术领域真正难的地方在哪（从痛点切入，而非从新闻切入）
3. `## 技术解析`：核心机制/架构/原理讲透，配代码或结构示意
4. `## 实践`：上手方法、典型用法、真实约束
5. `## 启示/对比与权衡`：与已有方案对比表，或可迁移的工程启示
6. `## 小结`：3-5 条要点

新闻线索如需提及，只在摘要或开头一句话带过并附来源链接，不单列章节。

## 硬约束

- 标题从 `##` 开始，绝不使用 `#`
- 代码块必须标注语言（```java/```python/```bash/```text 等）
- 禁止出现：来源说明、归属说明、修改说明、Guide哥、本文转载、原文链接
- 禁止 VuePress 语法：`:::`、`<Badge`、`<ClientOnly`、`@include`
- 来源链接放在正文中自然引用，不堆砌

## 完成后

1. 运行 `npm run build` 确认构建通过
2. **不做任何 git 操作**（不 commit、不 push）——把文件路径和选题理由报告给维护者，由人工审核后提交
